# 2026-10-23

## 修复 A5：MySQL Schema 摘要必然失败（`KeyError: 'numeric_precision'`）

用户报错原文：「mysql 未能获取表结构与方言提示（'numeric_precision'），本次回答可能不准确；请确认数据源可连通后重试。」—— 这是 10-20 加的 A2 降级提示在起作用，底层是真异常。

### 根因

pymysql 的 `DictCursor` 用**服务端返回的字段名**做键；MySQL / OceanBase 的 `information_schema` 列名是大写的。`mysql_adapter.get_table_columns` 里除 `numeric_precision` / `numeric_scale` 外都起了别名，所以只有这两列以 `NUMERIC_PRECISION` / `NUMERIC_SCALE` 返回，`r["numeric_precision"]` 直接 KeyError → `schema_summary()` 整体失败。

**同源未爆的坑**：`get_table_indexes` 的 `non_unique` / `column_name` / `index_type` 同样未起别名，摘要链路先崩所以没走到。

### 修复

- `mysql_adapter.py` 新增 `_Row(dict)`（大小写无关查找，保留原始键以便 `SELECT *` 列名原样展示），`_query()` 统一返回 `_Row` —— 一处覆盖所有未起别名的 I_S 列，OceanBase / GoldenDB 复用同适配器自动受益。
- `base.py` 抽出 `summary_schemas()` 钩子，`schema_summary()` 改调它。
- `mysql_adapter.summary_schemas()`：优先只用 `database_name`，否则过滤 `information_schema/mysql/performance_schema/sys/oceanbase`。**关键**：只修 KeyError 不够 —— `information_schema` 按字母序排最前，摘要会变成一堆系统表，比失败更误导。
- `mongodb_adapter.summary_schemas()`：其 `get_tables` 忽略 schema 参数、始终用当前库，原实现把同一份摘要重复 5 遍。

### 排查中确认无需改动的部分

- **Oracle**：`oracle_adapter._query()` 已用 `cols[i].lower()` 统一转小写，无此问题。
- **PostgreSQL**：`information_schema` 列名本身小写，且 `get_schemas()` 已过滤 `pg_catalog/information_schema/pg_toast`。
- **SQLite**：`PRAGMA database_list` 返回小写键。

### 踩坑记录

- **`Path.read_text()` 会把 CRLF 归一成 LF**：首次打补丁后 `base.py` / `mysql_adapter.py` 的 CRLF 全部变 0，diff 会炸。改用 `read_bytes().decode()` + `splitlines(keepends=True)`，新增行沿用锚点行的换行符，diff 保持在 +9/+49 行。
- 仓库里有 **10-20 15:44 遗留的 `.git/index.lock`**（上次会话崩溃留下），导致 `git checkout` 失败，已删除。
- `grep "^# "` 在这个仓库的 shell 里常返回空（编码/换行相关），改用 Grep 工具更可靠。
